Public30 schema-2 history

Use a reviewed Python runtime with SQLite and America/Los_Angeles timezone data.
Choose a new, empty public history directory and a binding file outside that
directory. Run the following from FCM-Companion with your explicit paths:

  python -B public_history_stage.py --root PUBLIC_ROOT --binding BINDING --initialize-empty
  python -B public_history_stage.py --root PUBLIC_ROOT --binding BINDING --archive APPROVED_RAW_SCAN
  .\Publish-FCMPublicHistory.ps1 -Python ABSOLUTE_PYTHON_EXE -Root PUBLIC_ROOT -Binding BINDING

Specify --archive again for another approved RawScans Lua file. Each needs its
adjacent, original metadata sidecar. The process does not discover sources,
start a task, read live SavedVariables, or adopt an existing legacy database.
Provider tables are excluded. Keep originals and private roots outside this
public store.

Publication writes PublicHistory.generated.lua only, with an 8 MiB limit and a
verified backup of the previous file. If a reader blocks replacement, the
previous export stays active and the same publication command can be retried.
After publication, use Update & Reload to load the new data. A generation
expires at Pacific midnight. Reprocessing approved scans preserves their source
timestamps. Storage and generation limits remain bounded. This workflow does
not activate cleanup.

The legacy collector and a separate private provider remain independent. A
legacy schema-1 export cannot supply schema-2 history. If the host is bound to
private history, an unavailable private export does not fall back to public data.
